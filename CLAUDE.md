## What this is

PLINKC ("Pocket Link Cache Device Driver", ver 1.62) is a resident device driver for the
**Sharp PC-E500 series pocket computer**. It installs a disk-like drive named `L:` that is
backed not by real storage but by a serial (SIO) link to a PC running a "Pocket Link System"
server (`PLINKM`, or the RAM-drive server `APLINKS for Win32`/`Another APLINKS for Macintosh`).
Once installed, standard pocket-computer BASIC commands (`COPY`, `SAVE`, `LOAD`, `LOADM`) work
against `L:` and transparently read/write sectors over the wire. A small sector cache (FAT + data)
speeds up access.

The repo now contains **both ends of the link**: the pocket-computer driver (`PLINKC.*`, the
device that speaks the protocol) and the PC-side server it talks to (`APLINKS/`, the host that
answers). If you touch the wire protocol on one side, the other side is your reference/regression
check — they must agree byte-for-byte.

This is a historical archived project (source dated 1999). The driver targets the
**SC62015 (ESR-L) CPU** and the vintage **A62 assembler v2.2.0**; the servers are Win32 and MS-DOS
binaries. Neither the assembler nor the target hardware is present, so there is no local
build/test/lint toolchain and no CI. Work here is almost entirely reading and editing the assembly
source and understanding the wire protocol.

## Reading the files — encoding matters

Encoding is **not uniform** across the repo — check before you read:

- **PLINKC driver files** (`PLINKC.asm`, `PLINKC.DOC`, `README.DOC`) are **Shift-JIS with CR-only
  (`\r`) line endings**. The plain `Read` tool fails on them (sees binary / garbles the Japanese).
  Read them via `tr` + `iconv`:
  ```bash
  tr '\r' '\n' < PLINKC.asm | iconv -f SHIFT_JIS -t UTF-8
  ```
- **`APLINKS/` text files** use **CRLF** line endings. `APLINKS.C`, `readme.txt`, and `view.bas`
  are plain ASCII (readable directly); `APLINKS.DOC` is Shift-JIS (needs `iconv -f SHIFT_JIS`).
- **`Anleitung.txt`** is a French/German-titled machine translation of the manual in an extended
  8-bit Latin encoding (`iconv -f CP1252` or `-f LATIN1`), **not** Shift-JIS.

(`iconv -f SHIFT_JIS -t UTF-8` and `xxd` are pre-approved in `.claude/settings.local.json`.)
When editing `PLINKC.asm`, preserve CR line endings and Shift-JIS encoding — the A62 assembler
expects them (the README explicitly notes 改行コードはCR / "newline code is CR"). Note the source
now also carries some French comments (e.g. `Version de 128 Ko`); it is still ver 1.62.

## Files

### Pocket-computer driver (`PLINKC.*`)

- **`PLINKC.asm`** — the driver + installer source (SC62015 assembly, A62 v2.2.0 syntax). The one
  file you actually edit. Contains both the installer (`org $bf000`, runs once) and the resident
  driver body (`devmain:` onward).
- **`PLINKC.OBJ`** — the assembled installer binary (1554 bytes; earlier named just `PLINKC`).
  Regenerated by assembling `PLINKC.asm`; not hand-edited.
- **`PLINKC.BAS`** — an ASCII BASIC program that `POKE`s the machine-code installer into memory and
  `CALL`s it. Lines 20–62 are the installer binary re-encoded as a text POKE listing; line 999
  `CALL &BF000` runs it. This is how the driver is installed on a device that has no binary-transfer
  program — you transfer the `.BAS` as text and `RUN` it.
- **`PLINKC.DOC`** / **`PLINKC.docx`** — user documentation (v1.60). `.DOC` is Shift-JIS text
  containing both a machine-translated French section and the original Japanese section.
- **`Anleitung.txt`** — a translated (French/German) install-and-use manual for PLINKC, covering the
  PC-1480U as well as the PC-E500. Handy as a plain-language reference for the install procedure and
  error messages, but secondary to `PLINKC.DOC`.
- **`README.DOC`** — packing list, version history, and license (freeware; copyright N.Kon &
  D.Mizobata). Also lists CRC32/size for the installer binary and `PLINKC.BAS` — if you regenerate
  those artifacts, these checksums will change.

### PC-side server (`APLINKS/`) — the other end of the link

`APLINKS` ("Another pocket link file server") is the host program that answers the driver's sector
requests. Two versions are archived:

- **`APLINKS/v1.03/`** — the MS-DOS command-line server by N.Kon (1992–93). `APLINKS.EXE` is the
  original DOS binary (**untouched — keep it**); `APLINKS.DOC` the Japanese docs; `aplinks32.exe`
  is the modern build (do not overwrite `APLINKS.EXE`: the FS is case-insensitive, so `aplinks.exe`
  collides with it — always build under a distinct name).
  **`APLINKS.C` is the authoritative, readable specification of the wire protocol** — cross-check
  driver changes against it. It has been **modernized to ISO C (C99) and ported off `<dos.h>` to a
  `#ifdef _WIN32` / POSIX platform layer**, so it builds and runs on current Windows *and* Linux/macOS:
  - Windows: `gcc -x c -std=c99 -O2 -o aplinks32.exe APLINKS.C` (also clang / MSVC `cl`).
  - POSIX: `cc -std=c99 -O2 -o aplinks APLINKS.C`.
  - The `.C` extension makes the `gcc`/`clang` *driver* assume C++ — pass `-x c`. (Editor clangd may
    also flag `#include <glob.h>` on Windows: a false positive — it parses the POSIX branch because
    it doesn't define `_WIN32`; both real compilers build clean.)

  The virtual-disk logic and on-wire protocol are **byte-for-byte unchanged** (verified against the
  driver's `rcv_sect`: a sector is `sectsiz+1 = 129` bytes on the wire — do not "fix" the 129th-byte
  handling in `sread`/`swrite`, it is deliberate). Platform layer: serial I/O →
  `CreateFile`/`ReadFile`/`WriteFile` (Win32) or `termios`+`read`/`write` (POSIX); file globbing →
  `FindFirstFileA` or `glob()`; `farmalloc` → `malloc`. The serial **port and baud are runtime
  options**: `aplinks32 -p COM3 -b 19200 [files...]` (`-h` for usage); defaults `COM1`/`9600` (Win)
  or `/dev/ttyUSB0`/`9600` (POSIX).

  **128K / 512K disk mode** (added; the 1993 original was 128K-only): per `PLINKC.DOCX`, 512K support
  "just switches the MPB" — same protocol, only the geometry changes. The server now carries both
  layouts (from the driver's `mpb128`/`mpb512`): `-1`/`-5` picks the mode for **preloaded** files
  (default 128K), and the driver's `'S'` handshake at INIT (`INIT "L:5"` / `"L:1"` on the pocket)
  **auto-switches an empty disk**, like APLINKS for Win32. Geometry is a set of runtime vars
  (`g_data_start` 44/80, `g_dir_top` 12·128/48·128, `g_data_sectors` 980/4016, `g_fat_bound`
  982/4018) set by `set_geometry()`; buffers are sized for the 512K max (`MAX_SYSBUF`,
  `MAX_DATA_SECTORS`). If files were preloaded in one mode and the pocket asks for the other, the
  server keeps its mode and warns (preload layout can't be relaid out mid-session).

  **Serial control lines — the non-obvious part that makes hardware work** (validated end-to-end on
  a real PC-E500, 2026-07): the pocket transmits *only while its CS input is high, and CS is driven
  by the PC's RTS* (PC-E500 Tech Ref p.54). So the server MUST assert **RTS=ON**
  (`RTS_CONTROL_ENABLE`) or it receives nothing (symptom: verbose heartbeat dots but no `S`/`R`/`W`
  lines); **DTR=OFF** (`DTR_CONTROL_DISABLE`). This is set in `open_serial` and overridable with
  `--rts on|off` / `--dtr on|off`; the banner shows the current state. **XON/XOFF must stay OFF**
  (`fOutX=fInX=FALSE`) because PLINK carries raw binary sectors (0x11/0x13 occur in data) — this is
  unlike the sibling text tool in `C:\Claude\Sharp transfert serial` (`sharp_pc_e500s_comm.c`, the
  reference that revealed the RTS behavior), which *does* use XON/XOFF. On the **pocket** side open
  the SIO with `OPEN "9600,N,8,1,A,L,&1A,N,N":CLOSE` (flow field `N`, not `X`; the `L`=CR+LF field is
  required). `-v` verbose mode logs every command + sector and an idle `.` heartbeat — the key
  debugging tool. Full round-trip confirmed: `SAVE "L:x"` (writes tokenized binary + 16-byte header,
  or `,A` for ASCII) → `INIT "L:D"` flushes to a PC file; preloading a file lets the pocket `LOAD` it.
- **`APLINKS/v1.02/`** — **APLINKS for Win32** (GUI) by Y.Akagawa (1996–97), based on Kon's 1.03.
  `aplinksw32.exe` (main GUI, drag-and-drop files, Win NT/95), `aplnksRes.dll` (resources),
  `delkey.exe` (clears its registry settings), `readme.txt`, `view.bas`. This is the server the
  512 KB mode of PLINKC was built to talk to. Disconnect from the pocket side with `INIT "L:D`.

### APLINKS modernization — status & how to resume (as of 2026-07-22)

**Validated on a real PC-E500**, both directions and both capacities: 512K `SAVE`→`INIT "L:D"`
flush produced a byte-faithful PC file; preload + pocket `LOAD`/`FILES` works; 128K non-regression
pass also confirmed. The build is `aplinks32.exe` (gcc/clang/MSVC, clean at `-Wall -Wextra`).
User-facing docs: `APLINKS/v1.03/README.md` (full usage/troubleshooting, French); repo docs carry
512K addenda (`README.DOC`, `APLINKS/v1.03/APLINKS.DOC` are now UTF-8 French; `v1.02/readme.txt`
English). Deep session history/rationale lives in the auto-memory `aplinks-512k-port-state.md`.

To resume after more hardware testing: reproduce with `aplinks32 -p com1 -b 9600 -5 -v` + pocket
`OPEN "9600,N,8,1,A,L,&1A,N,N":CLOSE` / `INIT "L:5"`; read the `-v` log (`[S]/[R]/[W]/[D]/[?]`).

**Feature batch added 2026-07-22 (compiles clean gcc+clang; disk-folder/preload path tested via a
dead port; serve-loop bits NOT yet hardware-tested):**
- `-d <dir>` **disk folder**: auto-preloads every file in it at startup (so `FILES "L:"` works with
  no per-file arg) and flushes pocket files back to it. Default = cwd (no auto-preload there — only
  explicit `[files...]` — to avoid loading the program's own files). Implemented via `preload_disk`
  / `preload_one_pattern` / `disk_path`; explicit files still preload as before. Options must come
  BEFORE positional files (parse stops at the first non-`-` arg).
- **Keep serving** after `INIT "L:D"`: `epilogue(int keep_serving)` — `'D'` calls `epilogue(1)`
  (flush → `reset_disk` → re-`preload_disk` → `serial_purge` → return); **Ctrl-D** calls
  `epilogue(0)` (flush + exit); Ctrl-C = hard quit.
- **Timestamps**: preload stamps the dir entry date/time (0x16-0x19, FAT format) from the file
  mtime; flush restores mtime via `set_file_mtime` (`_utime`/`utime`).
- **POSIX `--rts/--dtr`** now applied via `ioctl(TIOCMSET)`. **`-l <file>`** tees the verbose log
  (`vlog`). **`'I'` clear**: its 0x00 bytes are now silently swallowed (no `[?]` spam). Max Sharp
  baud is **19200** (`-b 19200`); already supported. Build scripts: `build.ps1`, `Makefile`.

Still to verify on hardware: keep-serving reconnect, and timestamp round-trip. Flush overwrites
existing files by design (disk-folder model). Remaining nice-to-have: none critical.

**v1.04 additions:** a `VERSION` macro ("1.04"), `print_banner()` (shown at startup and at the top
of `usage()`, crediting N.Kon + the 2026 update by Jean-François Albouy), and `print_free_space()`
— free space in KB and %, computed by walking the FAT (`get_fat(n) == 0` ⇒ free cluster) so it
counts preloaded *and* pocket-written files. It prints after the disk folder is loaded, on each
disconnect, and on exit; `on_sigint()` (installed via `signal(SIGINT, …)`) makes Ctrl-C print it
too before quitting (Ctrl-C does NOT flush — Ctrl-D and `INIT "L:D"` do). Useful capacities:
122 KB (128K) / 502 KB (512K).

**Session history (added after v1.04):** an in-memory timestamped log of high-level actions —
`hist_add(fmt, …)` appends a line (`HH:MM:SS  text`, stored in `g_history[HIST_MAX][HIST_LINE]`),
`hist_print()` dumps it (and tees to the `-l` log). Events recorded: start (mode/port/baud/folder/
files), per-connection read+write counts (`g_conn_reads`/`g_conn_writes`, incremented at the
`sread`/`swrite` calls, summarized+reset in `epilogue`), each saved file with size, and
disconnects with free space. Shown on demand by pressing **`h`** in the console, and automatically
on exit (Ctrl-D via `epilogue(0)`, Ctrl-C via `on_sigint`). NOTE: the old `ctrl_d_pressed()` was
replaced by `poll_console()` which returns the pressed key (0 if none); the idle loop dispatches
`0x04`→quit and `h`/`H`→history. Applied to BOTH sources.

**Two parallel sources — do not merge them without being asked:**
- `APLINKS.C` → `aplinks32.exe` (build.ps1 / Makefile, `-std=c99`) — the **reference**, the one
  validated on hardware. Leave it alone unless the user says otherwise.
- `APLINKS_C17.C` → `aplinks32_c17.exe` (`build_c17.ps1`, `-std=c17`) — a **readability variant**:
  identical behavior, but `bool` flags (`g_mode512/g_verbose/g_rts/g_dtr`, `want512`,
  `first_sector`, `bool` predicates and `set_geometry`/`epilogue` params) plus four file-scope
  `static_assert`s locking the geometry invariants. Both compile clean on gcc+clang at
  `-Wall -Wextra`, and both binaries come out byte-identical in size — the C17 change is purely
  compile-time, with **zero runtime effect** (`-std` is not an optimization switch; `-O2` is).
  gcc here is 14.2.0, which supports c99/c11/c17/c23.

## Build / assemble / install

There is no build script and no assembler in this repo. The historical workflow is:

1. Assemble `PLINKC.asm` with **A62 v2.2.0** → produces the `PLINKC.OBJ` installer binary. (Before
   v1.20 the project used the XASM assembler.)
2. On the pocket computer, either `LOADM "PLINKC"` then `CALL &BF000`, or `RUN` `PLINKC.BAS`
   (which POKEs the same code and installs it). Installation prints `Installed.` or an error
   (`Already exists.`, `Not enough memory.`, `Over two pages.`).
3. The PC-side server (e.g. APLINKS for Win32) must be running, with serial set to **9600 bps or
   faster, N,8,1** (`OPEN "9600,N,8,1,A,,,N":CLOSE`).

There are no unit tests — behavior is verified against real hardware and the PC server.

## Architecture / how the driver works

**Installer (`entry:`)** — runs at `org $bf000`. It: checks `L:` isn't already installed and that
a free memory block exists; picks a variable device number (default 10); finds an install location
that doesn't straddle a 64K page boundary; relocates the driver code to that address (the reloc
table after `prgend` is walked to fix up addresses); links the driver header into the IOCS device
chain at `[iroot]`; and repairs BASIC's `BTEXT$`/`BDATA$` pointers (`linkbas`). Constants at the
top define hardware register addresses (`sio_ctrl_reg $f7`, `sio_stat_reg $f8`, `sio_rx_reg $f9`,
`sio_tx_reg $fa`, etc.) and IOCS/FCS entry points.

**Driver body (`devmain:`)** — invoked by the OS for each device operation. It saves interrupt
state, redirects the SIO receive vector to its own `rcv` handler, forces 8-bit SIO mode, asserts
DTR/RR, dispatches on the IOCS command byte in `main:`, then restores SIO params/vector and reports
BREAK-key state on exit.

**IOCS command dispatch (`main:`)** — the command number arrives in `il`:
- `$10` init/no-op, `$11` get media-parameter-block, `$12`/`$15` read sectors, `$13`/`$14` write
  sectors, `$16` no-op, `$17` single-sector read with buffer-hit check, `$18` get-root (DS
  support), `$3f` init (select 128K/512K mode, send `S`+size or `D` or `I` handshake), `$40`
  get-root directory. Unknown commands return error code 3.
- **Wire protocol** is byte-oriented over SIO: the driver sends a single ASCII command char
  followed by a 2-byte little-endian sector number and, for writes, 129 bytes of cached sector data
  plus an `$ff` end marker, then awaits an ack. Driver side: `send_sect`, `rcv_sect`, `send_one`,
  `receive_one` (chars `'S'` set-size, `'D'`, `'I'` init/clear, `'W'` write). The **server side**
  in `APLINKS/v1.03/APLINKS.C` is the readable counterpart — its main loop is
  `switch (get_com())` with cases `'R'` (read sector), `'W'` (write sector), `'D'` (dump/disconnect,
  flushes the RAM drive back to real files). When changing the protocol, keep both sides in sync.

**Sectors & caching** — sector size is **128 bytes** (`sectsiz`). The cache is `n_fcache = 7` FAT
sectors + `n_dcache = 1` data sector. Two **Media Parameter Blocks** describe the two supported
capacities: `mpb128` (128 KB: 980 data sectors, 12 FAT sectors, 128 max files) and `mpb512`
(512 KB: 4016 data sectors, 48 FAT sectors). Command `$3f` picks the MPB based on whether the PC
server reports `'1'` (128K) or `'5'` (512K), and patches sector-count references accordingly. These
constants line up with the server: `APLINKS.C` uses `DIR_TOP = 12*128`, a `44*128` system buffer,
data sectors beginning at 44 (`dtop`), and a `data_sector[980]` array — matching the driver's
`mpb128` layout, so the two agree on the on-wire disk geometry.

## Editing conventions

- Assembly uses A62 idioms: `pre $30/$32` internal-RAM addressing prefixes, `rel` for
  relocatable/PC-relative operands, `mv`/`ex`/`callf`/`pushu`/`popu`, and the custom `#DEFMACRO bsr`
  (relative subroutine call). Match the surrounding style and column-aligned tab layout.
- Comments in the source are Japanese (Shift-JIS). Keep new comments consistent with the file's
  existing language and encoding rather than introducing UTF-8.
- Version history and the bug-fix rationale for each release live in `README.DOC` — recent releases
  (1.61, 1.62) were both bug fixes to command `$17`. Update that history when bumping the version.
